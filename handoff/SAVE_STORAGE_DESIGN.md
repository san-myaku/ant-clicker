# 保存と復旧の損失なし圧縮

ブラウザの現保存と復旧用保存だけをgzip/Base64で損失なく圧縮する `save-codec.js` を追加した。モデルの保存形式living-clicker-2/キーlivingClicker_2は維持し、書き出し/読込のJSONと個体の位置・歩行履歴・経路・荷・仕事は変えない。現在の同じ形式の非圧縮保存も検証して読めるが、起動時には書き換えず、以後の実保存で圧縮する。livingClicker_1とその復旧を含む他のキーは読込/変換/削除しない。

ストレージの包みはliving-clicker-storage-1 / gzip-base64 / 元のUTF8バイト長 / CRC32 / data。fflate0.8.3をpackage-lockで固定し、生成view.jsへ同梱（MIT全文付き）する。外部CDN/新しい公開パスは追加しない。最大展開長16,000,000バイト、gzipヘッダ・長さ・CRC32・UTF8・内側の形式を検査してから、従来のSimulation.restoreによる全台帳/参照/空間検証を通す。CRC32は破損検知であり認証ではない。壊れた圧縮保存は起動/保存時に上書きせず、明示的な復旧でのみ候補を採用する。

- `npm ci --ignore-scripts` と編集元からの `npm run build` に成功。core.js/lifecycle.js/game.js/index.htmlと旧公開index.htmlは前回からhash不変。生成view.jsはbuild-view.cjs/save-codec.js/固定依存から生成し、直接編集していない。
- 固定20保存で圧縮→復元のJSONがバイト一致。Nodeの独立したzlibでもgzipの元JSONを一致確認。破損/未知形式/過大サイズなど24件を拒否、モデルの不正参照も圧縮で通過しない。900秒/128匹/256匹を各600コマ進めた結果も非圧縮からの継続と全保存一致。
- 256匹: 2,186,320→542,925文字（75.17%減）。元のJSONは2,187,554 UTF8バイト。容量の単位を混同しない。履歴を短くしたり座標を丸めたりしていない。
- Chromium1440/393幅で、約1.10M文字の旧キーを保持したまま、現在256匹を通常保存→リセット→復旧→再読込、明示的な保存の読込、128匹JSONの取込→復旧が一致。実ダウンロードした256匹JSONも元の保存hashと一致。前回容量不足だった同じ併存条件が通るようになった。
- ブラウザの実保存枠を埋めたケースでは、リセットを拒否して現在/復旧/旧キー/充填キーすべてを保持。実書き出しと再起動後の状態も一致。単に容量エラーをモックした証拠とは分けた。壊れた圧縮保存の保護と実UIによる復旧も合格。
- `node prototypes/living-clicker/verify-all.cjs --browser --chain`: **26本すべて合格**、621.239秒、終了コード0。Nodev24.22.1 / Playwright1.62.1 / fflate0.8.3 / Windows / 16論理コア。76ソース/依存と23入力のhashは前後一致。ソースmanifest SHA256 `56598ff41f784566206374359725c9de3ecdbbc12a34266e2176b8c9aa2ca3ce`。今回の新規→128匹保存は前回の自然256匹入力before-256.jsonとバイト一致。256匹までの自然育成全体を再実行した意味ではなく、同じモデルhashの前回結果に接続する。

結果は実行完了後に記録。実行結果/固定入力は置き換えず `qa/storage-20261027/` に保持した。ブラウザ検証は保存の生文字列とモデルを別に比較し、復号したモデルが完全一致し、保存の生バイト列が失敗前後で不変である条件を維持した。検証を容量削減の数値に合わせて緩めていない。

同期圧縮なので保存時の処理時間は残る。実ブラウザ操作の往復時間はsave-browser-results.jsonへ記録してあり、圧縮単体の時間/実機性能/実効10倍とは扱わない。実機iPhone Safari、512/1000匹での容量/速度/継続は未確認。容量を無制限にしたわけではない。次は第3層/512匹の研究・供給・育児・実容量を同時に接続し、実保存と退避容量も再測定する。main/Pages/PR/push/既存配信先への反映なし。
