# 姿勢判定キャッシュの数値化 — 採用結果

2026-10-28、codex/ant-1000-plan-20261027。比較元は82cb191（物体索引・部屋分類共有済み）。

既存の姿勢判定キャッシュを、長い文字列の作成/Map検索から、131,072枠の数値配列へ置き換えた。活動512匹2入力を含む8保存で全状態のバイト一致を確認し、全33本の回帰後に採用した。1000匹の解放はこの変更に含めていない。

## 採用した範囲と安全条件

- 編集元はbuild-pose-cache.cjsとbuild.cjs。core.jsはnpm run buildで生成。game.js/lifecycle.js/view.jsは前版と同一。
- x/yはFloat64の値を保持し、向き16通りと荷の種類も一致した場合に限り回答を再利用。スロットを選ぶ計算で同じ番号になっても、実座標が違えばmissになる。座標を丸めた答えを使う処理ではない。
- 成功/境界拒否/遮る砂粒の番号という既存の回答形式を維持。砂粒が掘られて消えた時の再計算も維持。容量満杯では別の回答を捨てるだけで、実際の幾何検査へ戻る。
- キャッシュ対象は元のignore=-1/margin=.045のみ。移動時の.025、別余白、砂粒を指定して無視する検査、掃引そのものは変更しない。Museの「証明を持ち運ぶ移動」や全体のイベント監視基盤を採用したわけではない。
- 復元時は新しく作り、保存形式へ内部キャッシュを追加しない。本人の掘削/地表運搬、全物体、通行/予約/台帳を維持。

## 画面を動かした通常速度の観測

採用後のHeadless Chromiumで1440px/393pxを順番に測定。各幅で同じ実512匹保存を読み込み、UIから実深度IV研究を支払って新需要を作り、通常速度1xへ。2秒の準備後に10秒間、実モデルのstep時間とrAF時刻を計装した。台帳/進捗/最終保存の復元一致/入力とソースhash/コンソール例外なしを確認。

## 初回の生成失敗

新フックのexport対象を、先行build-actorsがACTOR_MAX/MAX_ACTORSを追加する前の文字列で指定したため、ちょうど1箇所のガードが拒否した。本体やcore.jsへ未適用。続く比較は未生成coreで開始できず、初回の生成器/失敗をr1-generation-failedへ保持した。実際の変換後exportに合わせ、ガードは維持して再生成した。依存処理は前段の成功後に順番に実行する。PROJECT_CONTEXT失敗33にも記録。
