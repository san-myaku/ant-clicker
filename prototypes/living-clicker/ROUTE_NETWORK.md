# 実空洞の経路共有

2026-10-27。編集元は `route-network.js`、組み込みは `build.cjs`。`core.js` は生成物。人口上限と保存形式はこの工程では変更しない。

## 共有する範囲

完成した掘削履歴と創設時の入口から、部屋の出入口を結ぶ有向の網を導く。部屋番号は接続候補を選ぶ手掛かりだけであり、実際の身体と荷の掃引が通る区間だけを辺にする。未完成の掘削先、同室、近距離、退避中は従来の細かな探索を使う。共有経路を構成できない場合も従来の探索で判定し、空洞を増やしたり通行条件を緩めたりしない。

長い移動は、部屋間の接続候補を幅優先で選び、その候補の網に目的地からの距離場を作る。距離場の値には実区間の長さと旋回コストを含める。全ての部屋間の絶対最短経路を保証するものではない。現在必要な方向・荷姿だけを遅延生成し、空荷、卵、餌、土の各荷姿、ゴミ、クッキーを別に扱う。

出発位置から最初の出入口、最後の出入口から目的地は各個体の局所探索で接続する。部屋内の接続は実際の部屋タグの範囲を通り、従来の16方向・身体/荷・旋回の検査を残す。部屋の中心への強制経由は追加しない。地表は変化する土山を含むため局所探索を毎回行い、入口の掘削履歴の地表端と従来の進入姿勢を保持する。

## 無効化と保存

掘削等の `invalidateNavigation(cell)` で周辺の部屋の版を更新し、関係する部屋内接続と区間だけを作り直す。通路の境界は身体/荷の余裕を含めて扱う。無関係な通路の原本は残す。距離場はプロファイルごと64件、部屋内接続は2048件まで。原本を凍結し、個体へは独立した経路を返す。進捗、荷の所有、譲り/待避は個体側にある。

索引・共有原本・距離場は保存しない。保存/読込で初期化される派生データであり、暖まったキャッシュと空のキャッシュからの継続が一致するか専用検証を行う。開発時は `sim._routeNetwork?.report()` で探索/再利用/無効化の回数を取得できる。画面へ実装説明は追加しない。

## 居室の床の探索

経路の選び方が変わった自然育成で、実際には休める床があるのに候補が0になる問題を確認した。従来は1セルの代表的な運搬姿勢だけを休息候補としていた。`game.js` の `homeSpots` で既存の半単位の立ち位置4点を調べ、身体・他個体・荷・女王との間隔の検査を通す。必要な間隔、空洞、部屋容量は増やさない。

居室検証には深度用の保存を流用せず、自然に次の居室の計画が始まる直前の専用保存 `qa/housing-demand.json` を使う。元の `before-depth.json` は保持する。出典/ソースhashは `housing-demand-provenance.json`。1200秒の掘削待ち、300秒の移動確認、実掘削・徒歩移動・混雑減少の合格条件は維持する。深く掘れず場所がない場合は、この需要のある開始状態から独立に確認する。

`node prototypes/living-clicker/verify-all.cjs network housing` で専用確認、`--browser --chain` で全体と自然育成を確認する。完了した結果・入力とソースhash・性能測定は [検証記録](qa/VERIFICATION.md) に記載する。初回の組み立て時間と再利用後の時間を分け、経路の違う自然育成を全保存一致の最適化と混同しない。
