# 統合確認版の保存の土台

2026-10-23。対象は `/clicker/`。公開本編 `index.html`、観察試作 `/`、育成試作 `/play/` の保存は変更しない。

## 一式として保存する状態

同じ確認版キー `grainClicker_1_antSimV23_0` に、`format: ant-clicker-grain-save`、`schema: 1` を付ける。経済の版識別は `v: 23.0`。地層/探索の追加後の粒世界は `clicker-grain-2`。旧grain-1も検証し、形/仕事/荷物を維持して地質を追加し、起動時に更新を保存する。

grain-2は固定seed/境界/岩/鉱脈、探索した壁/実到達/発見/採掘/受領台帳/収入端数、工事への予約参照を持つ。`g.timeScale` は1〜10の整数（旧保存で欠落なら1）。新規の小さい配置は新規開始時だけで、旧保存の輪郭/空洞/担当/荷物を新配置へ置き換えない。地層の定義はCSS座標、実世界の幾何は保存DPRから換算する。

- `g`: 元本編が保存していた資源、人数/配役、強化/研究、成長ゲージ、予約、遠征、目標、トロフィー、直近50件の日記等。
- `world`: 巣の形/可視室/工事進捗/地表に加え、掘削の時計・作業・建築係・実粒・荷物のID/位置/搬出記録。保存時DPRを持ち、復元先に換算する。
- `permanent`: 知見と恒久研究。通常状態と同じ保存に含め、読込時は最初の倍率/容量計算より先に適用する。
- `recovery`: 読込/転生/やり直し直前の状態を一つだけ保持。通常の保存でも維持する。元の状態と置換先を一回の `localStorage.setItem` で確定させる。
- `rejectedRaw`: 読めない保存から復旧した場合、その元の文字列を保管する。通常保存で消さない。

表示設定/研究画面の表示設定は従来どおり端末側の別キー。書き出しは現在の進行と恒久研究を持ち出すもので、過去の復旧履歴や表示設定の全履歴ではない。

## 読込と持ち出し

形式/版、必須の型、有限の数値、資源/人数/レベルの範囲、研究ID、部屋/通路/作業/個体/荷物の参照と重複、砂粒の取得元・所有者・数量等を採用前に検証する。巨大入力/深すぎる構造や危険なオブジェクトキーも拒否する。検証した同じオブジェクトを適用し、途中でストレージを読み直さない。

無関係なJSON、元の公開版、観察/育成試作、未知の版は読み込まない。既存の確認版の保存だけは起動時に検証し、旧別キーの知見と一緒に新しい一式へ移す。既存の掘削途中の仕事・荷物・形を保持する。旧キー `grainClicker_1_antSimV22_2` への自動フォールバックと、旧転生用キーを使う処理は外す。

書き出しはボタンを押した時の状態を新しく取得する。UTF-8の日本語/絵文字を含むBase64をコピーし、コピーが使えない時はJSONファイルを保存する。容量不足でローカルに保存できない時も、現在の状態の書き出しは使える。読込はこの版のBase64/JSONを検証し、巣と知見を置き換えることを表示して確認する。復元先の知見との加算・最大値合成はせず、一式を正確に置き換える。

起動時に読めないデータがある場合はプレイと自動保存を止める。元のデータの書き出し、正常なバックアップの読込、明示的な初期化を選べる。読込/初期化が書込に成功するまで旧データを置換しない。読めない元データは復旧後も保管する。

## 保存する時点と失敗

雇用、強化、研究/恒久研究、部屋予約、遠征等の重要な操作は、その操作と達成報酬を反映して保存する。手動産卵の連打は250msでまとめる。自動保存は30秒ごとに更新全体の終了後へ回し、`pagehide` と非表示への移行では同期的に保存する。

容量不足/書込失敗では旧保存を維持し、「保存できていない」表示と再試行/書き出し操作を出す。進行中のメモリ状態は保持する。自動保存の失敗後に毎フレーム書込を繰り返さない。OSによる予告のない終了など、ブラウザが離脱イベントを発火しない場合の直前の自動進行まで無損失と保証するものではない。

転生は新しい巣と知見の報酬を同じ保存で確定し、保存成功後だけ再読込する。途中の別キー加算/削除は使わず、失敗時は報酬もリセットも適用しない。再読込で知見を再加算しない。現在の保持対象は知見/恒久研究、転生回数/生産ボーナス、日記の直近記録、トロフィー、戦歴。目標達成は新しい周回で判定し直す。メニューの「一つ前に戻す」は巣と知見を同時に戻す。

## 実装と確認の入口

`persistence.js` は検証/一式の取得/原子的な書込、`save-integration.js` は元ゲームの操作/寿命イベントとの接続。`build.cjs` がHTMLへ組み込み、公開本編の正本は編集しない。`nest.js` は実仕事/物体/空洞と地質/探索を同時に保存する。保存基盤の初回作業では未設定の向き/作業を初期値へ揃えた範囲だったが、その後の地層統合では実仕事の規則も更新している。現在の責務は [共通契約](WORLD_WORK_CONTRACT.md)、検証は [DEPTH_VERIFICATION.md](qa/DEPTH_VERIFICATION.md) を参照する。

確認手順:

```
node prototypes/clicker-integration/build.cjs
node prototypes/clicker-integration/check-save.cjs
node prototypes/clicker-integration/check.cjs
node prototypes/clicker-integration/check-delivery.cjs
```

最終結果は `qa/save-checks.json`、`qa/checks.json`、`qa/delivery.json` と `qa/SAVE_VERIFICATION.md`。テストは隔離したブラウザ保存で行い、利用中の保存を検証用に書き換えない。

## 残る範囲

これは保存のP0を先に直す工程。全ての蟻の実仕事を保存する新モデル、卵/餌の物理化、通常/放置の共通規則、終盤全機能の復元、一周の転生体験の設計と検証は後続工程。元本編の代表アクター/群れと、保存されない一時イベントも残る。全保存課題や公開条件が完了したとは扱わない。

一つ前の状態を同じキーに含めるため保存量は増える。容量不足は安全に失敗させるが、大量の搬出土/大人口の保存量の上限はN/A/Uで測定が必要。実機iPhoneの離脱・復帰、ブラウザ/OS側のデータ消去、複数タブの同時プレイによる競合は今回の合格範囲に含めない。
