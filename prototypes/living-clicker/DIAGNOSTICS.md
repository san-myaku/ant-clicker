# 停止診断（開発用）

通常は無効。画面上の操作や保存キーは追加していない。`diagnostics.js` が読み取り専用の観測、`view-diagnostics.js` がブラウザ接続の編集元。`build-view.cjs` が `view.js` に埋め込む。これらの編集元やQAデータを公開サーバーの許可リストへ追加しない。

## 使う

ブラウザの開発者コンソールで、問題が起きる前に開始する。

```js
await colonyGame.startDiagnostics();
// 通常の操作で巣を進める。
const report = colonyGame.stopDiagnostics();
// 実行中にも colonyGame.diagnostics() でコピーを取得できる。
```

開始時に配信されたHTML/4スクリプトのSHA256を取得する。通常の保存には診断記録を混ぜず、ゲームの再開/初期化で監視を止める。終了したレポートは `colonyGame.diagnostics()` で取得できる。保存や外部送信を自動で行わない。

Nodeでは `require('./diagnostics.js').Observer` を作り `.attach(sim)` / `.detach()`。`metadata` へ実行元のhash等を渡す。`step()` とタップ/配分/研究/警報の公開メソッドだけを包み、元の戻り値と例外を維持する。通常時のシミュレーションには診断の呼び出しを追加していない。

## 何を記録するか

- 完了した更新の30コマごとに、実座標、仕事/荷、次の経路点、待ち相手と譲り、枝で作業中の仕事、搬出/給餌等の数を読む。経路探索・容量判定・キャッシュを作る問い合わせは呼ばない。
- `waitingFor` と `yieldHold` の向き付きの関係から待ち閉路を探す。進んでいる個体や短い待ちは停止とせず、持続して動かない閉路を20ゲーム秒で記録する。`yieldFor` は状況として残すが、それだけで待ち関係とは断定しない。
- 割り当て済みの仕事/荷/移動が60ゲーム秒変化しない個体を記録する。全対象の無進行がさらに続けば全体の無進行も記録する。休息、正の待ち時間、戦闘、気絶は別の状態として扱う。産卵や幼虫の待ち時間だけでは異常にしない。
- 消えた待ち相手/仕事/荷/給餌先/運び手と、自由な未静止物体が物理更新の集合にない状態を、1ゲーム秒の持続後に記録する。瞬間の一時状態で即停止と判断しない。
- 移動/掘削/仕事の段階が変わると無進行の時計を戻す。ゲームの待ち時間や状態を解除する処理は持たない。シミュレーションの例外は記録後に同じ例外を投げ直す。

これらは疑わしい状態の診断で、到達不能や全種類の停止を証明するものではない。割り当て前の仕事選択不能・容量不足・地形の分断を網羅的に分類する処理はまだない。経路や粒の現物は保存と候補個体から調べる。

## 保存と再現

30ゲーム秒ごとの完全保存を最大2件、直近の観測を120件、異常記録を4件保持する。異常が増えて古い記録が外れた数は `droppedIncidents` に残す。各異常には利用可能な先行保存、そこからの操作/時間刻み、現在の完全保存または `captureError` を含む。壊れた状態を有効な保存と偽らず、最後の有効な先行保存を残す。

操作は `tap` / `shiftRole` / `buyResearch` / `alarmAt` と、画面の産卵切替/速度設定。時間刻みは同じ連続値を連長で保持し、`.advance()` の0.1秒刻みや端数も記録する。各先行保存の操作列が256項目に達した時にも保存を更新する。保持量は無限に増やさない。

再現は先行保存を `Simulation.restore()` し、操作列の `step` を同じ `dt/count`、`call` を同じ引数、`setting` を同じ値で実行する。診断資料のハッシュと同じソースを使う。専用検証で保存の全一致を確認する。

任意のコンソール代入、独自の試験フック、物体を直接動かすコード等を自動で記録できるわけではない。監視開始前の操作も先行保存より前へ遡れない。ブラウザの描画時刻やページの一時停止は世界の更新回数と分け、記録した世界の操作/刻みを再生する。

診断は完全保存・記録の分だけ追加コストを持つ。1000匹での負荷/長時間の誤検出は未確認。通常プレイの性能値と、診断を有効にした性能値を混同しない。
